# go/

- `gen/` — generated by `dagr build` (module `otlpgen`, `layout="package-per-graph"`):
  one package per signal — `otlptraces`, `otlpmetrics`, `otlplogs`, `otlpprofiles` (lazy
  accessors, arena, serializer), each with its `…direct` value-tree builder — and one
  DataSink package per spool (`spanlog`, `metriclog`, `logrecordlog`, `profilelog`).
  The imported `OtlpCommon` is its own package pair, `otlpcommon` + `otlpcommondirect`,
  which the four signal packages refer to; `otlpprofilesgraph` holds it as vtable nodes
  and keeps its own copy. Not committed.
- `internal/seed/` — the deterministic 500-span batch, a port of `otlp_seed()` from the
  Dagr repo's `benchmarks/proto_vs_dagr` (same LCG, same draw order).
- `internal/fixture/` — that seed materialised as `ptrace.Traces`; a WIDE batch per
  signal (`wide.go`: every field pdata can express, every union variant, the awkward
  shapes); and realistic metrics / logs / profiles batches for the benchmark
  (`signals.go`).
- `internal/coverage/` — proves a fixture is wide instead of trusting it: walks the
  direct-builder value tree by reflection and names every field that is never present
  and every union variant that never occurs.
- `pdatabridge/` — `pdata.Traces` ⇄ Dagr bytes. Encode via the direct builder; decode
  exists for compatibility and is the slow path by construction. Attribute values recurse
  through Slice and Map (`array_value` / `kvlist_value`); the decoder bounds its own
  recursion at `MaxValueDepth`.
- `metricbridge/`, `logbridge/`, `profilebridge/` — the same for `pmetric`, `plog` and
  `pprofile`. Decoders walk arrays with the generated cursors, never `{F}At(i)`.
- `shm/`, `shmexporter/`, `shmreceiver/` — the same-host metrics hop (Dagr spec/38 §7.1):
  the `MetricsRegion` SharedBuffer in a file both processes map (`gen/metricsregion`), an
  OTel Go SDK exporter that publishes each export as one seqlock write, and the
  `dagrshm` collector receiver that polls a directory of regions. `shmdirect/` is the
  SDK-free path: bound instruments that update an atomic `MetricsValues` region in place
  (Dagr spec/40 §2), read by the same receiver. `cmd/shmdemo` and
  `cmd/shmbench` are the apps `../ocb/roundtrip.sh` (phase C) and `../ocb/samehost.sh` run.
- `commonbridge/` — the shared-message conversions (attributes, `AnyValue`, `Resource`,
  `InstrumentationScope`) and the encode/decode helpers all four bridges use, written
  once against `otlpgen/otlpcommon`.
- `profilegraphbridge/` — `pprofile` ⇄ `OtlpProfilesGraph`, the experimental graph form
  of profiles: indices become node references on the way in (one arena node per
  dictionary entry), and the dictionary is rebuilt from each node's `BufferPos()` on the
  way out. Gated on the resolved data, not the dictionary's order.
- `bench/` — the measurements in the top-level README (`signals_test.go`: metrics, logs,
  profiles).
- `spool/` — the spool file behind both components, for any `spool.Signal`: create or
  resume, append, read forward or newest-first, and decide whether the tail is intact.
  The four sinks share their framing, so the tail logic is shared; `signal.go` adapts
  each generated sink. Nothing here parses a record body.
- `exporter/` — `dagrfileexporter`, a collector exporter for traces, metrics, logs and
  profiles (`xexporter`). `Consume*` → direct builder → one appended record, one spool
  per pipeline. Implements the consumer interfaces directly: the spool *is* the queue, so
  there is deliberately no `exporterhelper` queue in front of it.
- `receiver/` — `dagrfilereceiver`, any spool back into an unmodified pipeline
  (`xreceiver`). The slow path by construction (it materialises), and documented as such.
- `store/` — the query surface over a spool (spec/38 §6.2, §6.3): `Query` reads spans
  newest-first as lazy handles and reports what the walk actually cost, `Ring` bounds the
  spool by compacting from the tail without reading what it drops, and `Sampler` is a
  tail sampler that keeps one flat summary per trace instead of every span of every
  undecided trace.
- `cmd/otlpdagrctl/` — the round-trip harness `ocb/roundtrip.sh` drives: `send` a batch
  over OTLP/HTTP, `spool` to report and check a spool, `verify` a dump against what was
  sent — each with `-signal traces|metrics|logs|profiles`.

```
go test ./...                                       # every gate
go test ./bench -bench . -benchmem -benchtime 500x  # the read/encode numbers
go test ./bench -run TestSignalSizes -v             # metrics / logs / profiles vs protobuf size
go test ./exporter -bench ConsumeTraces -benchtime 2s
go test ./store -bench . -benchtime 2s              # crash ring + lazy vs pdata decisions
../ocb/roundtrip.sh                                 # through a real ocb-built collector
```
